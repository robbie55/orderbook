# Design — low-latency limit order book + matching engine

Single-instrument, C++20. This doc records the locked architectural decisions
and the staged build plan. It is the interview-defensible narrative in prose;
the README will carry the diagram + benchmark numbers once they exist.

## Locked decisions

**Prices are integer ticks.** No floating point anywhere. One `Price` == one
tick; scaling happens at the feed boundary.

**Book: direct-indexed array (primary) + `std::map` reference (oracle), one
concept.** The primary book is a `std::vector<Level>` indexed by
`price − band.floor`, giving O(1) add / cancel / find-level. Best bid/ask are
moving indices advanced inward when a level empties. A `std::map`-backed
`ReferenceBook` implements the same `BookLike` concept and serves as the
correctness oracle *and* the benchmark baseline. Both are exercised by one
templated differential harness — the Blargg/acid2 discipline from the emulator,
translated: a golden/randomized command stream must leave both books in
identical state.

- Concept, not an abstract base class: the harness and benchmarks are templated
  on the concrete book, so there is **no vtable / indirect call** on the hot
  path.
- The array's honest weakness is a bounded price band; fine for one liquid
  instrument. Fallback for unbounded/many-symbol is a hot-band array + cold hash
  map. The empty-level advance is the one non-O(1) spot and will be backed by a
  hierarchical occupancy **bitmap** (`__builtin_ctzll` next-set-bit) as a
  low-latency flourish.

**Order lookup: dense-id flat vector.** `id → Order*` via a `std::vector<Order*>`
indexed by `id − base`, assuming ITCH-style monotonic session refs. One load, no
hashing. If a target feed turns out to use sparse ids, swap in an open-addressing
flat hash map (`absl`/`boost` flat) — measured against `std::unordered_map`.

**Nodes from the pool allocator.** `Order` is an intrusive FIFO node (≤ 1 cache
line, no back-pointer to its level — the level is recovered from `price`),
allocated from the existing `PoolAllocator`. `include/ob/object_pool.hpp` is a
drop-in **seam**: a real free-list-over-aligned-slab placeholder so tests are
meaningful now; the production allocator replaces it and owns the benchmark
numbers.

**Concurrency lives only at the queue boundary.** The book is single-threaded by
construction — matching one order is an atomic critical section because one
thread owns the book. The Week-6 SPSC ring buffer crosses the feed→book thread
boundary (single-producer/single-consumer, so still single-writer book). This is
the answer to "is your book thread-safe?": it doesn't need to be.

## Matching rules (Stage 3)

Price–time priority. Fills print at the **passive** order's price. Limit rests
its remainder; Market/IOC cancel the remainder; **FOK is check-then-commit** —
pre-scan crossing volume via `Level::total_qty`, reject atomically if short, only
then execute. Modify: size-down keeps time priority (edit in place); price change
or size-up loses it (cancel + reinsert at back). Self-trade prevention: one
policy behind a flag.

## Build stages (each gated by tests, CPU-before-PPU style)

1. **Types + Order + pool seam + `BookLike`** — construction/alignment,
   static_asserts, tick round-trip, pool alloc/free + `bad_alloc` on exhaustion.
   *(this commit)*
2. **ArrayBook + ReferenceBook add/cancel/modify** — differential test on
   randomized op streams, ASan-clean.
3. **Matching: limit → market/IOC/FOK → STP** — hand-built scenario suite.
4. **Benchmark harness** — micro (per-op) + macro; median trials, DCE guards,
   outlier rejection, -O3.
5. **Feed handler** — ITCH-style parse (big-endian), golden replay reproduces a
   known book state.
6. **SPSC ring buffer + latency histogram** — p50/p99/p99.9, benchmarked vs a
   mutex queue.
7. **README + freeze (v1.0).**
